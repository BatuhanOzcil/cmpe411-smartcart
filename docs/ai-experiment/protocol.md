# SmartCart measurement plan

Frozen code and written requirements are from Git commit 1d8be2f4eb1ce99439d24aafefd3d833ff145dfb. The existing suite is the AI-assisted baseline. The generated suite contains only approved candidates, including any explicitly recorded repairs. The combined suite is their union. Count each collected pytest case once. Record code and branch coverage as distinct measurements. The report uses the same Python and package versions for all groups.

Keep the original nine selected mutations as the primary comparison. Before inspecting any generated candidate, define a supplemental diagnostic set against three specification interactions. M10 substitutes half-even rounding for the coupon only. M11 treats a recognized but ineligible coupon as a reason to skip membership. M12 changes the HTTP membership default from False to True. Both M11 and M12 are positive controls for the decision table and transport defaults. M10 probes whether passing the generic rounding mutation implies coverage of coupon ties. Apply one mutation at a time, across every group, in separate temporary copies. Clean runs must pass first. Collection failures are errors. Keep supplemental results distinct from the original nine.
